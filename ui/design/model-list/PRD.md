## 1. 概述

* **模块名称**：模型仓库列表页 (Model Repository List)
* **功能定位**：作为 MatrixHub 平台模型资产的全局聚合大厅，提供模型的展示、检索、筛选和导航入口。
* **开发边界声明**：页面顶部的全局导航栏（Logo、主菜单、语种切换、用户头像等）为**公共组件**，不在本页面的开发范围内。本页面仅负责开发公共 Layout 下方的核心内容区（侧边栏 + 列表区）。

## 2. 权限与数据可见性规则

数据隔离是本页面的核心逻辑，需前后端严格配合。当前登录用户在列表中看到的全部数据，应为以下两者的**并集**：

1. **公开模型 (Public Models)**：平台内设置为“公开”Project 下的所有模型数据，对平台所有用户（含未加入该 Project 的用户）均可见。
2. **私有模型 (Private Models)**：平台内设置为“私有”Project 下的模型数据，**仅对拥有该 Project 权限的用户可见**（角色包括：Project Admin / Editor / Viewer）。

## 3. 页面布局与路由状态

* **路由集成**：本页面作为子路由组件加载，嵌入在包含顶部导航的公共 Layout（如基于 TanStack Router 的 `__root`）中。
* **状态同步 (URL Search Params)**：页面的所有核心筛选状态（全局搜索词、左侧分类标签、排序方式、分页页码）**必须同步到 URL 参数中**。确保用户刷新页面或分享链接时，当前的筛选状态不会丢失。

## 4. 顶部操作区 (Top Action Bar)

位于核心列表区域顶部，控制全局展示状态。

* **全局模糊搜索**：
* 交互：输入框，支持回车触发或防抖实时触发。
* 范围：支持根据“模型名称”或“标签”进行模糊检索。


* **排序控件 (Sort Dropdown)**：
* 提供下拉选择器。
* 排序字段：`更新时间` (默认)、`参数量`。
* 排序方式：支持 Icon 按钮切换升序 (Ascending) 和降序 (Descending)。默认按 `更新时间` 倒序排列。



## 5. 左侧多维筛选边栏 (Sidebar Filters)

提供多维度的快速过滤能力，包含三个 Tab：**任务、框架、项目**。各 Tab 下的选中状态取**交集 (AND)** 过滤右侧列表；同一 Tab 内的多选项取**并集 (OR)**。

* **通用交互**：每个 Tab 顶部包含一个独立的本地搜索框，仅用于在**当前筛选项列表**中进行高亮模糊过滤，不触发后端模型数据请求。
* **【任务】Tab (Tasks)**：以标签群组形式平铺展示任务类型（如：文本生成、图像到图像等），支持多选。
* **【框架】Tab (Frameworks)**：以带有独立 Icon 的标签形式展示（如：GGUF, PyTorch, TensorFlow 等），支持多选。
* **【项目】Tab (Projects)**：
* 列表形式展示项目卡片，支持单选/多选。
* 显示内容：项目名称、权限标识（`公开` 绿色 Tag / `私有` 黄色 Tag）、统计数据（模型数、数据集数）。



## 6. 核心卡片列表区 (Main Content Area)

内容区分为上下两个独立版块。切换筛选条件、搜索、翻页时，列表区域应有骨架屏 (Skeleton) 或 Loading 动画。

### 6.1 热门模型 / 推荐模型 (Featured Models)

* **位置**：页面最上方（仅第一页显示）。
* **数据来源**：由运营在后台配置的内置/置顶模型。
* **展示限制**：采用横向平铺布局。**默认展示 2 个模型卡片，最多不超过 3 个**。若数据超过 3 个前端仅截断展示前 3 个；若无数据，该区块整体隐藏。

### 6.2 全部模型列表 (All Models)

* **位置**：推荐模型下方。
* **缺省状态**：当筛选无结果时，展示规范的“暂无数据”空状态插画与提示，并提供“清空筛选条件”快捷按钮。
* **分页机制**：底部提供标准分页器 (Pagination)。
* 展示总条目数。
* 支持切换每页展示数量（如 10条/页）。
* 支持手动输入页码跳转。



## 7. 模型卡片组件 (Model Card) - 详细设计

模型卡片是本页面的核心原子组件。

### 7.1 交互与路由跳转

* **Hover 状态**：设计稿中**唯一的颜色差异**体现在卡片的 Hover 效果上。默认状态保持基础色调，鼠标悬浮时触发边框高亮（参考 UI 稿主色/青色边框）。
* **跳转详情页**：
* 卡片的**标题区**（或整卡）需支持点击交互。
* 点击后利用现有路由（如 `<Link to="/models/$modelId">`）跳转至对应的【模型详情页】，本需求不包含详情页开发。



### 7.2 卡片内部布局与字段对齐

* **第一行：标题区 (Title Area)**
* 格式：`[所属项目名称] / [模型名称]`。
* 样式：单行显示，超长部分 CSS 截断 (`text-overflow: ellipsis`)。


* **第二行：特征标签区 (Feature Tags)**
* **强制排序逻辑**：1. 任务标签（主色底，带 Icon） -> 2. 模型参数量（如 `171B`，带 Icon） -> 3. 框架标签（如 `PyTorch`，带 Icon）。
* **折叠逻辑**：卡片宽度固定，当标签数量 > 3 个或宽度不足时，多余标签隐藏并显示 `...` 按钮。Hover/点击 `...` 按钮时唤起气泡浮层 (Popover) 展示完整标签。


* **第三行：元数据区 (Metadata) 【严禁错位】**
* 采用 Flex 布局实现两端对齐 (`justify-content: space-between`)。
* **左侧居左显示**：带 Icon 的所属项目名称 + 模型大小（规范单位如 `595 GB`，需前端修正设计稿中 `BG` 笔误）。
* **右侧强制右对齐**：更新时间（格式化为 `YYYY-MM-DD HH:mm`）。



## 8. 技术选型建议 (前端实现参考)

* **UI 组件库**：强烈推荐使用 Mantine UI 构建此页面。左侧边栏可组合使用 `Tabs` 和 `TextInput`；模型卡片可使用 `Card` 配合 `Group`, `Badge` (任务标签), 以及 `Popover` (`...` 气泡悬浮) 快速实现高度还原。
* **路由与数据同步**：推荐使用 TanStack Router，其一流的 Type-Safe 路由特性和强大的 Search Params 管理能力，能完美解决“筛选状态同步到 URL”的需求。
* **异步数据状态**：配合 TanStack Query 处理列表的 Fetch、缓存及分页状态，将 URL 解析出的 Params 作为 Query Key 依赖，实现优雅的数据驱动渲染。
