# Product Requirements Document (PRD): MatrixHub Model Repository

## 1. 概述 (Overview)

* **模块名称**：模型仓库列表页 (Model Repository List)
* **目标**：提供一个统一的、高性能的模型资产聚合大厅。支持用户通过多维度筛选、搜索和排序，快速检索全平台公开模型及个人有权限的私有模型。
* **开发边界**：页面顶部的全局导航栏（Logo、主菜单、语种切换、个人中心）为**公共组件**，不在本页面的开发范围内。本页面仅负责该公共 Layout 下方的核心内容区呈现。

## 2. 权限与数据可见性 (Data & Permission Rules)

数据隔离是本页面的核心逻辑，后端接口需严格过滤，前端需做好状态标识。

* **公开模型 (Public Models)**：所有属于“公开”Project的数据。对平台全员可见（无论是否加入该Project）。
* **私有模型 (Private Models)**：所有属于“私有”Project的数据。**仅对该 Project 的成员可见**（包含 Project Admin / Editor / Viewer 角色）。
* **列表呈现总集**：当前用户看到的列表 = `全平台公开模型` ∪ `当前用户有权限的私有模型`。
* **卡片标识**：UI 上不需要在每个卡片上强制标注公开/私有，但如果用户在左侧“项目”Tab中查看，项目本身会有“公开(绿)”或“私有(黄)”的 Tag。

## 3. 功能需求说明 (Functional Requirements)

### 3.1 页面级路由与布局 (Routing & Layout)

* 本页面作为子路由组件加载。建议通过基于文件或配置的路由系统（如 TanStack Router）的 `__root` 布局包裹，共享顶部导航。
* 页面的所有筛选状态（搜索词、分类标签、排序方式、分页页码）**必须同步到 URL 搜索参数 (URL Search Params)** 中。这确保了用户刷新页面或分享链接时，当前的筛选状态不会丢失。

### 3.2 顶部操作区 (Top Action Bar)

* **模糊搜索 (Fuzzy Search)**：
* 交互：输入框，支持敲击回车或防抖触发（建议 300ms 延迟）。
* 范围：支持根据“模型名称”或“标签名称”进行模糊检索。


* **排序控件 (Sort Dropdown)**：
* 下拉菜单，包含选项：`更新时间` (默认)、`参数量`。
* 升降序切换：提供 Icon 按钮切换升序 (Ascending) 和降序 (Descending)。
* 默认行为：默认按 `更新时间` 倒序排列（最新上传/更新的排在最前）。



### 3.3 左侧多维筛选边栏 (Sidebar Filters)

采用多 Tab 结构（任务、框架、项目），各 Tab 内部的选中项之间为**并集 (OR)**，不同 Tab 之间的筛选条件为**交集 (AND)**。

* **Tab 1: 任务 (Tasks)**
* UI 展现：标签群组（如“文本生成”、“图像到图像”）。
* 交互：支持单选/多选（根据产品具体定义，通常为多选）。


* **Tab 2: 框架 (Frameworks)**
* UI 展现：带独立 Logo Icon 的标签（如 PyTorch, TensorFlow, GGUF）。


* **Tab 3: 项目 (Projects)**
* UI 展现：列表卡片，显示项目名称、权限 Tag（公开/私有）、模型数量。


* **本地搜索**：每个 Tab 顶部包含一个独立的小搜索框，仅用于在**当前筛选项列表**中进行高亮模糊过滤，不触发后端模型数据请求。

### 3.4 核心卡片列表区 (Main Content Area)

#### 3.4.1 热门模型 / 推荐模型 (Featured Models)

* **位置**：页面最上方（仅第一页显示）。
* **数据来源**：由平台运营在后台通过置顶或打标推荐的模型。
* **UI 展现**：横向平铺，最多显示 4 个模型卡片。若接口返回无推荐数据，该区块整体隐藏。

#### 3.4.2 全部模型列表 (All Models)

* **位置**：推荐模型下方。
* **分页机制**：采用标准底部 Pagination 组件（不采用无限滚动加载）。
* 显示总数据条数。
* 支持切换每页显示条数（如 10条/20条）。
* 支持快速跳转页码。


* **缺省与加载状态**：
* **Loading**：初次加载或切换 URL 参数时，展示卡片骨架屏 (Skeleton)。
* **Empty**：当所有条件交集无结果时，展示规范的空状态插画与提示文案（如：“未找到匹配的模型”），并提供“清空筛选条件”的操作按钮。



### 3.5 模型卡片组件设计 (Model Card Component)

卡片是本页面的核心原子组件，任意位置点击均触发路由跳转至【模型详情页】。

* **第一行：标题区**
* 格式：`[所属项目名称] / [模型名称]`。
* 超长处理：单行显示，超出部分 CSS 截断 (`text-overflow: ellipsis`)。


* **第二行：特征标签区 (Feature Tags)**
* **强制排序逻辑**：
1. 任务标签（主色底，带任务 Icon）
2. 模型参数量（如 `171B`，带参数 Icon）
3. 框架标签（如 `PyTorch`，带框架 Icon）


* **折叠逻辑**：卡片宽度固定，当标签数量大于 3 个，或宽度不足以完全展示时，多余标签隐藏，显示 `...` 按钮。
* **悬浮交互**：Hover `...` 按钮时，唤起浮层 (Popover) 展示所有被折叠的标签。


* **第三行：元数据区 (Metadata)**
* 项目名称：带项目 Icon。
* 模型大小：数值 + 规范单位（如 `595 GB`，需前端统一纠正设计稿中 `BG` 的笔误）。
* 更新时间：格式化为 `YYYY-MM-DD HH:mm`。



## 4. 技术实现指导 (Technical Implementation Guidance)

* **组件库选型契合度**：建议充分利用现有的 UI 组件库（如 Mantine）来快速构建卡片和左侧边栏。Mantine 的 `Tabs`, `Badge`, `Card`, 和 `Popover` 组件能高度还原此设计。
* **表单与状态**：针对左侧复杂的筛选条件组合，建议使用专门的表单状态管理工具来追踪用户的多选状态，并在用户确认（或 debounce 后）将状态序列化为 URL 参数，而不是直接将庞大的 state 对象塞入组件内部。
* **数据获取**：列表接口由于受多个筛选项、分页、排序组合影响，建议使用声明式的数据请求库，将 URL Search Params 作为依赖项（Query Key）。当 URL 变化时，自动触发后台数据的重新拉取和缓存。
